# 插件简易使用说明

面向「装好了、想马上用」的场景。原理与排错见 [仓库格式规范](repo-format.md) 和 [README](../README.md)。

---

## 1. 首次配置

Playnite → `设置(F4) → 扩展 → Playnite Vault`

| 项 | 填什么 | 说明 |
|---|---|---|
| WebDAV 地址 | `http://192.168.1.10:5006/vault/` **必须以 `/` 结尾** | 这是 NAS 上 WebDAV 服务的根路径 |
| 用户名 / 密码 | NAS 的 WebDAV 账号 | 有些 NAS 要用「应用密码 / 独立密码」，**不是**登录后台那个密码 |
| 本地安装根目录 | `D:\Games` | 从 NAS 装回来的游戏会放到 `<它>\<子目录名>\` |
| 走系统代理 | **别勾** | 访问内网 NAS 时必须关掉，否则请求会被本机代理（Clash 等）截走 |

填完点右下角的 **测试连接**。它会直接告诉你问题在哪 —— 包括把 401 拆成
「密码错」和「服务端认证后端坏了」两种情况（见下面排错）。

其余几项一般不用动：

| 项 | 默认 | 什么时候要改 |
|---|---|---|
| 区块大小 | 32 MB | 单并发传不到 20 MB/s 时可以试 16；磁盘紧张不用改 |
| 停滞超时 | 30 秒 | 「传着传着速度到 0」—— 它管的就是这个。链路很差时调到 60 |
| 应答超时 | 180 秒 | NAS 特别慢（合并/落盘要很久）才需要调大 |
| 并发下载路数 | 6 | HTTPS 千兆内网建议 6；明文 HTTP 用 1~2 就够 |
| 并发上传路数 | 4 | 瓶颈通常在 NAS 写入侧，所以比下载保守一档 |
| 归档时压缩 | 关 | 游戏资源多为已压缩格式，开了也省不下多少，还会变慢 |

> 设置界面的每一项下面都有一行灰字，写的是「为什么是这个默认值」。

## 2. 安装 / 更新插件（用解包器，免手工拷文件）

插件**没法在运行的时候替换自己** —— `PlayniteVault.dll` 被 Playnite 进程锁着
（Windows 文件锁，实测就是 Permission denied）。所以换机器、重装 Playnite、
或者从改名前的 `VaultDemo_*` 目录换到 `Playnite-Vault`，都需要「从外面装一次」。
解包器把这件事做成了按钮：底栏 → **安装插件到 Playnite…**

窗口里三步就完事：

1. **Playnite 目录** —— 会自动填好；不对就点「浏览…」，选有
   `Playnite.DesktopApp.exe` 的那个文件夹；点「自动检测」也能再找一次
2. **插件包** —— *用内置的*（和解包器一起发布，不用联网）或 *GitHub / Gitee 最新*
3. 点 **注入并重启**

它按这个顺序做，每一步都写进窗口里的日志：

| 步骤 | 做什么 |
|---|---|
| 1 | 定位 `Extensions` 目录，读出当前装的是哪个版本 |
| 2 | 取插件包（内置的，或联网取最新 release） |
| 3 | **优雅地请 Playnite 退出** —— 等于点窗口右上角的 ×，不是强杀 |
| 4 | 写进 `Extensions\Playnite-Vault\`，旧版本挪去备份 |
| 5 | 用**原来那个** exe（桌面版/全屏版）把 Playnite 重新拉起来 |

三点值得知道：

- **为什么必须先关再写**：dll 被 Playnite 占着，运行期覆盖不了。顺序不能反，
  所以是「先关 → 再写 → 再拉起来」，中途关窗也不会留下半个插件。
- **为什么不强杀**：强杀会让 Playnite 丢掉还没落盘的库改动。万一它没退出
  （常见原因是设置里开了「关闭到托盘」，点 × 只是收进托盘），工具会停下来问你，
  **不会**替你做这个决定。
- **旧版本不会被删**，而是挪到 `%APPDATA%\VaultUnpacker\plugin-backup\<时间戳>\`。
  改名前的旧目录 `VaultDemo_*` 也会一起挪走 —— 留着会让 Playnite 同时加载新旧两份插件，
  库里会出现两套一样的菜单。

> 已装的是哪个版本，进窗口第一屏就能看到；显示「**缺 dll**」就再注入一次。

命令行方式（适合脚本 / 无人值守）：

```
VaultUnpacker.exe --inject-plugin
VaultUnpacker.exe --inject-plugin --plugin-source gitee --no-restart
python vault-unpack.py --inject-plugin            （源码方式）
```

`--plugin-source` 可选 `bundled`（用 exe 内置的那份，离线可用）/ `auto` / `github` / `gitee`。
**带参数就是命令行、不带参数才是图形界面**；exe 是窗口程序没有控制台，所以命令行模式
建议把输出重定向到文件（`> log.txt 2>&1`），否则结果会写到 exe 同目录的
`vault-unpack-cli.log`。

## 3. 归档（把本地已有的游戏传到 NAS）

在 Playnite 库里选中游戏 → 右键 → **Vault → 归档选中应用到 NAS**。

会先把「要传哪些、多少字节」列出来让你确认一次，然后开始。
进度窗分两段：**打包**（本地读文件、切块、算哈希）→ **上传**（并发传区块）。

- **中断了不用管**: 同一个内容第二次归档几乎是空跑
  —— 区块是内容寻址的，每次上传前先 `HEAD` 问一句「这块你是不是已经有了」，
  有就跳过。所以传一半中断了，直接再点一次就行。
- 本地文件不会被删。
- 元数据（封面、开发商、类型、标签、评分、简介）随包上传，别的机器装回去不用重新刮削。

## 4. 在另一台机器上安装

先在这台机器上做同样的配置，然后：

1. 右键某个游戏 → **Vault → 从 NAS 刷新库条目**
2. 库里出现 NAS 上的所有应用；未安装的条目右下角有「安装」按钮
3. 点它 → 选「从 Vault 安装」→ 等着

安装位置是 `<本地安装根目录>\<子目录名>`，**子目录名就是上传前那个目录名**。
例如上传前在 `D:\Game\Lib\Plants Vs Zombies RH`，装回去还是 `Plants Vs Zombies RH`
—— 不会因为 Playnite 里显示的是中文名就变成中文目录。

> 看不到新条目？先检查左侧**过滤器面板的「库」**有没有只勾了某一项。
> 新手最容易卡在这一步。

## 5. 其他菜单项

| 菜单项 | 干什么 |
|---|---|
| 修复安装 | 只补缺失/大小不符的文件，已经一致的跳过。适合「玩到一半发现少文件」 |
| 测试仓库连接 | 连不上时的第一件事就是点它；会按错误类型给出可照做的排查步骤 |
| **检查插件更新** | 手动查一次插件自己的新版本（平时是启动后自动查，见第 6 节） |
| **从 NAS 刷新库条目** | 手动让本机库跟 NAS 对齐（也可以让它自动刷，见第 7 节） |
| 打开插件数据目录 | 看 `local-index.json` / `settings.json` / `state.json` |
| 打开插件日志 | `playnite-vault.log`，排查问题的第一现场 |
| **管理仓库应用（删除）** | 见第 8 节 |

## 6. 自动更新（插件给自己升级）

打开 Playnite 大约 12 秒后，插件会同时去 GitHub 与 Gitee 的 release 对一下版本号。
**有新版就自己下载、校验、替换、重启 Playnite**，不需要你做任何事。

| 设置项 | 默认 | 说明 |
|---|---|---|
| 启动时自动检查更新 | 开 | 关掉之后就只在你手动点「检查插件更新」时才查 |
| 更新前先询问 | 关 | 打开后每次发现新版都先弹窗给你看更新说明；点「否」= 跳过这个版本 |
| 下载镜像 | 自动 | 「自动」= 两个源都探一遍、谁快用谁；也可以锁死 GitHub 或 Gitee |

三点值得知道：

- **它会自己换源**。两个源**并发**探测、按实测延迟排序，快的当主源；
  下载途中速度掉到地板（默认 40 KB/s）以下就自动换另一个源。
  两个源都低于地板时，还会用主源**不设速度限制**再跑一次 —— **慢 ≠ 装不上**。
- **更新是「退出之后才替换」**。插件文件正被 Playnite 占着，运行期覆盖不了。
  所以它会请求 Playnite 退出（和托盘「退出」是同一条路，不会把下次启动带进安全模式），
  退出后由后台脚本替换文件、再把 Playnite 重新打开。
  万一自动退出没成功，它会提示你手动退（**从托盘图标右键选「退出」**），退出后同样会完成更新。
- **跳过某个版本**：弹窗里选「否」会把那个版本记进「跳过版本」，之后不再提示。
  想装的话回设置页点 **清除「跳过版本」**。

手动检查：右键游戏 → **Vault → 检查插件更新**。

## 7. 自动刷新远端库

设置页里打开之后，插件会定时去 NAS 拉一次索引，让本机的库自动跟 NAS 对齐。

| 设置项 | 默认 | 说明 |
|---|---|---|
| 自动刷新远端库 | 关 | 打开后下面两项才生效 |
| 刷新间隔 | 30 分钟 | 5 分钟 ~ 24 小时之间都可以 |
| 启动后也刷新一次 | 开 | 启动 25 秒后先刷一次（等 Playnite 自己把库导入完再动手） |

三条省心的保证：

- **索引没变就不动本地库**。每次比的是索引指纹，而指纹**刻意不包含索引的更新时间**
  —— 所以「重新归档了一遍、内容其实没变」不会引发一次没意义的库重写。
- **运行游戏时自动暂停**，游戏结束后把该补的补上 —— 不抢 NAS 带宽、不拖慢游戏。
- **归档 / 安装正在跑的时候也让路**，不会两个方向一起压 NAS。

刷新失败不会打扰你：只有**真的改了库**或**出错**时才发通知。
连续失败时刷新间隔会自动指数放宽（最多 8 倍），免得 NAS 不可达时每 5 分钟就去敲一次门。

手动刷新：右键 → **Vault → 从 NAS 刷新库条目**，或设置页点 **立即刷新远端库**。

## 8. 管理仓库（删除 NAS 上的归档）

**v1.8.1 起在侧边栏那一页里直接删**（见第 11 节）：本机游戏铺成卡片墙，
传过的卡片上有「删除」；仓库里有、本地库里已经没有的条目另列一栏，也能删。
右键菜单 → **Vault → 管理仓库应用** 那个窗口仍然在，但只剩「改管理口令」这一件事。

第一次用到删除时会提示设置**管理口令**（至少 4 位）。之后每次删都要输一次，
删之前还会先弹一次确认。

关于这个口令，有两点必须说清楚：

- **它保存在仓库根的 `vault-admin.json`，不在本机**。换台机器用同一个仓库，
  自动就能读到，不需要重新设置。
- **它是防误触闸门，不是权限系统**。WebDAV 账号本身就有删除权限，
  能操作这个 NAS 目录的人绕过插件照样能删。
  真要隔离权限，得在 NAS 侧给不同账号配不同目录权限。

删除会删掉 `apps/{Id}/` 整个目录（含全部区块），**本地已下载的文件不受影响**。
删除不可撤销。

## 9. 重新归档（升级到 v3 / 修目录名）

从旧版本升级上来时建议做一次，这样旧归档也能拿到新的 32 MB 切块和正确的目录名。
**顺序很重要**：

1. **如果本地那个目录还装着游戏且打算保留同名文件，先备份**
   —— 重新安装会往同一个路径写，同名文件会被覆盖
2. 选中要更新的游戏 → 右键 → **Vault → 归档选中应用到 NAS**
3. 归档完后 → **Vault → 从 NAS 刷新库条目**
4. **卸载**旧的那条记录（不会动 NAS），再点「安装」重新拉下来 —— 这时目录名就是新的了

做完之后：

- 旧格式（v1 逐文件 / v2 分片）的残留目录会自动清掉
- 内容没变的文件通过内容寻址直接跳过，**实际只传变化的区块**
- 换过区块大小也不怕：归档结束时会把不在新清单里的旧区块回收掉

> **不用急着做这件事**。旧归档照样能装 —— 读取端 v1 / v2 / v3 全都支持。
> 重新归档只是为了「新切块 + 正确目录名」这两个好处。

## 10. 同步主题（Themes 目录 ⇄ 仓库）

主题是一堆小文件（xaml / yaml / 图片 / 字体），所以走的是**和游戏不一样**的存法：
仓库里 `themes/` 下面是**普通文件镜像**，结构和本地同构 ——
`themes/Desktop/{主题Id}/…`、`themes/Fullscreen/{主题Id}/…`，
外加 `themes/index.json`（每个主题一行指纹）和每个主题自己的 `manifest.json`（文件清单）。

好处是 NAS 上那棵树本身就是一份能用的主题库：可以直接浏览，也可以整个 `Desktop\*` 拷回本地。

用**仓库里的开发工具**（注意：不在发布包里）：

```
VaultPack themes-sync --dir "D:\Game\Playnite\Themes" --mode up --dry-run   # 先看会动什么
VaultPack themes-sync --dir "D:\Game\Playnite\Themes" --mode up             # 真正上传
```

- `--mode up`（默认，备份方向）只上传 / `down` 只下载 / `both` 双向
- `--dry-run` 只列计划不落盘；`--force` 无视指纹整树重传（用来修「指纹对得上但文件坏了」）
- 不写 `--dir` 时取 `%PLAYNITE_DIR%\Themes`；WebDAV 设置从插件数据目录里读，也可用 `--settings` 指
- 第二次跑是增量的：指纹一致的主题直接跳过，改过的主题只重传变了的文件

**冲突策略**（两边都动过同一个主题、又分不出谁是对的）：按修改时间定胜负，
**输的那一份原地留档**成 `{主题Id}.conflict-local-<时间戳>`（本地）或
`{主题Id}.conflict-remote-<时间戳>`（远端），一个字节都不丢。
`.conflict-` 开头的目录不会再被同步扫描。

**远端只增不减**：本地删掉一个主题**不会**连带删掉远端那份 —— 这里当备份档案用，
不是双向镜像。被删掉的那些只会在结尾的「远端独有」提示里列出来。

## 11. 侧边栏「仓库管家」（v1.6.0 起，v1.8.1 重做版面，v1.9.0 加任务页）

左侧边栏多了一个图标（矢量画的，不依赖字体），点开就是**一整页**控制台 ——
和「功成名就」那种插件页一样，嵌在主窗口里，不用另开窗口。

页面上分四块：

| 分栏 | 里面有什么 |
|---|---|
| 概览 | 仓库应用数 / 仓库体积 / 本地主题数 / 主题体积 / 冲突留档数；环形与条形图 |
| 主题 | **卡片勾选式**：本机与 NAS 上的主题各一张卡（带体积、状态），左上角「全选」；勾了哪几个就只搬哪几个，方向与预演在下面选 |
| 仓库 | **一张卡片墙管完两边**：本机库里的游戏 + 只在 NAS 上的条目铺在一起，标出「已归档 / 未归档 / 只在 NAS」与体积；未传的可直接归档、只在 NAS 的可取回本机或删除；可筛选、可按名字过滤 |
| 任务 | 传输队列的逐条视图：类型（上传 / 下载 / 主题）、进度、失败原因，能整体取消、能清除已结束的 |
| 设置 | 分「连接 NAS / 传输 / 自动化 / 云存档」四组，就地改（改完点页面下方的「保存设置」） |

几个要点：

- **小圆点挪到左栏「仓库管家」标题右边了**（原来贴右上角，正好压在 Playnite 的最小化 /
  最大化 / 关闭按钮上，点刷新会顺手把 Playnite 关掉）。它是连通状态：绿 = 连得上、
  黄 = 暂时连不上（NAS 没开机这类，等一会儿可能就好）、红 = 配置或凭据不对
  （地址写错、401、证书）、灰 = 还没配 WebDAV。**点它立刻重测一次**，探测期间会转圈。
- **页面底部那条进度条**是所有在跑 / 排队任务的合计进度，不切页就能看到。
  传输期间界面不锁 —— 可以继续翻别的游戏、改设置。
- **版本号就在左栏产品名后面**（`Playnite Vault @<当前版本>`）。
- **明暗可以手动指定**：设置里「界面」一节的「明暗档位」有 跟随 Playnite / 常亮 / 常暗 三档。
  自动判断按的是主窗口底色，主题把底色做成半透明或贴图时会判反 —— 那时候手动压回去。
- **「传过没有」是怎么判的**：按五级顺序对 —— Playnite 游戏 ID（`Game.Id`）→
  库内 ID（`Game.GameId`，Steam 游戏就是 appid）→ 安装目录名推出来的 Id →
  库内标识直接等于条目 Id（本插件导入的游戏就是这样）→ 游戏名字。
  卡片提示里会写明这一条是拿哪个键对上的。老归档（v1.8 之前）没存前两个键，
  目录改过名、本地那份又卸载了的时候，靠最后两级仍然能对上，**不会再重复出现两张卡**；
  实在对不上就重新归档一次。
- **删除要过管理口令**，而且口令闸门在插件里只有一道，
  卡片上删、右键菜单里删、改口令，走的都是同一处校验。
- 统计是**纯本地扫描**（不联网）：体积、冲突副本数都是当场数出来的。

## 12. 云存档（v1.7.0 起）

把**游戏存档**也放进 NAS：换台机器、重装系统之后能把存档拉回来接着玩。
游戏归档（第 3 节）管的是「游戏本体」，这一节管的是「存档」，两者互不干扰。

### 存档路径从哪来

两个来源合并，**Playnite 自己的优先**：

1. 你在 Playnite 里给这个游戏配的存档路径（游戏详情里的「存档」那栏）；
2. 插件自己的补充列表（在存档管理窗口里加的）。

两边按**游戏标题**归并，所以同一个存档配了两份也不会被当成两条。

路径里可以写变量。插件认这 8 个：

| 变量 | 展开成 |
|---|---|
| `{GameDir}` | 游戏安装目录 |
| `{UserProfile}` | 当前用户目录 |
| `{WinAppData}` | `%APPDATA%`（Roaming） |
| `{LocalAppData}` | `%LOCALAPPDATA%` |
| `{LocalAppDataLow}` | `%USERPROFILE%\AppData\LocalLow` |
| `{Documents}` | 文档 |
| `{SavedGames}` | 保存的游戏 |
| `{ProgramData}` | `ProgramData` |

另外，你要是照着 Playnite 官方文档写了 `{WinLocalAppData}`、`{WinSavedGames}`、
`%USERPROFILE%\Saved Games` 这类写法，插件在**读取时会自动翻成上表里的变量**
（`{InstallDir}` 也算 `{GameDir}`）。翻不动的会明确报出来，不会拿它当目录名去建。

### 怎么用

三个入口，进的是同一个窗口：

- 侧边栏「仓库管家」页 → **存档管理…**
- 主菜单 → **存档管理（云存档）**
- 游戏上右键 → **存档：存档管理（路径/快照/分支）**、**存档：上传到 NAS**

窗口左边是游戏列表，右边是这台游戏的**路径列表 + 快照列表**：

| 动作 | 说明 |
|---|---|
| 嗅探存档路径 | 跑三档自动探测（常见位置 / 会话差分 / PCGamingWiki），**只列候选**，你勾选才写进去 |
| 上传 | 打一份新快照进仓库 |
| 恢复 | 把选中的快照解回本地 —— **动手前会先把当前存档备份走** |
| 固定 | 固定过的快照**永远不会**被保留策略删掉 |
| 删除 | 删一份快照（会再确认一次） |
| 按策略清理 | 按「每个分支最多留几份」清，`0` = 无限 |
| 新建分支 | 给「多周目 / 多存档线」各开一条，各算各的保留份数 |

### 触发时机（设置里选，都能关）

| 模式 | 行为 |
|---|---|
| 手动 | 只有你点「上传」才动 |
| 停止游戏后自动上传 | 游戏一退出就传一份 |
| 停止后上传 + 启动时问 | 退游戏传；进游戏时若远端有更新的快照，先问你要不要拉下来 |

设置里还能改：**每个分支最多保留几份**（`0` = 无限）、**恢复前备份**、
**本地备份留几份**、**开不开会话差分嗅探**。

### 几条不会变的行为

- **绝不静默删你的东西**：任何删除都要明确确认；恢复是「先备份、再覆盖」，
  不是「先删干净、再写进去」。
- 存档内容按 SHA-1 **内容寻址**存放，同一份内容只占一份空间，跨快照、跨分支都算。
- 仓库里**不是本插件写的**存档索引会被直接拒绝，不会误改别人的东西。
- 命令行也能用：`VaultPack saves --action list|branches|upload|download|sniff`；
  `delete` / `prune` 还要额外给 `--allow-delete`。

## 13. 排错

### 401 未授权

测试连接会给出可照做的排查顺序，核心是这两者的区别：

- **浏览器里打开同一个 WebDAV 地址，用同一个账号也进不去**（或反复弹认证框）
  → 那是 **NAS 服务端认证后端的问题**，改插件的任何设置都不会有用。
  这种情况很常见，插件无能为力，得去 NAS 侧处理。
- 浏览器能进去、插件进不去 → 多半是**代理**没关，或者用户名/密码其实是错的
  （注意「应用密码 / 独立密码」这回事）。

> 顺带一句：**正确密码、错误密码、空密码三者返回的 401 响应是完全一样的**，
> 所以「看状态码」这件事本身就分不出原因，只能靠上面这种对照实验。

### 传着传着速度掉到 0 然后超时

这是「停滞」而不是「传输超时」。把 **停滞超时** 调大（比如 60 秒）通常就够了。
根因一般是 NAS 写入抖动或者单线路被限速。也可以试试把**并发上传路数**降到 2。

### 完全连不上 / 证书报错 / DNS 失败

测试连接会按 `WebExceptionStatus` 细分：域名解析失败、连接被拒绝、连接超时、
TLS 证书校验失败（自签证书 → 换正式证书或改用 http）、代理拦截 —— 都能一眼看出来。

### 装出来是中文目录名

说明这条归档是**旧版本打的包**，元数据里没有 `InstallDirName`。
重新归档一次就好了（见第 9 节）。

`打开插件日志` → `playnite-vault.log`。打包/上传/下载每个阶段的关键数字都记在里面。
